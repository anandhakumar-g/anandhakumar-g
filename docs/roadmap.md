# Single Point — Phased MVP Roadmap

Reprioritised for market reach and early revenue: the vendor marketplace / offers side moves
ahead of deeper ticketing polish, since that is where reach and initial profit come from.
Foundation still comes first. **Each MVP is built, released, and verified before the next set
is planned.**

| MVP | Theme | Contents |
|---|---|---|
| **MVP-1** | **Foundation** ✅ *shipped* | Resident onboarding (OTP + tenant/flat join via invite code or admin approval), raise ticket (photo + service location), admin view/resolve/assign/reroute, provider accept/update status, push notifications (outbox), single seeded global category list, manual provider verification, immutable status history, multi-tenant isolation (RLS + RBAC), token-based theming (Light/Dark/accent + tenant branding), entitlements seam. **No payment.** |
| **MVP-2** | **Vendor Marketplace & Offers** ✅ *shipped* | Vendor taxonomy expansion (food & dining, retail, travel, accommodation, events & entertainment), provider KYC upload + verification workflow (VERIFIED now gated on accepted docs), Offers/Coupons module with layered targeting, **Super Admin as validating authority for every offer** (incl. enquiry-based targeting off `request_type = ENQUIRY`), mandatory anti-fatigue controls (opt-in category subscriptions, central weekly frequency cap, digest mode, independent ticket/promo opt-outs), custom typography (Bricolage Grotesque + Plus Jakarta Sans) + deals feed. Dedicated React admin console **deferred** — admin/super-admin work lives in the Expo app (also runs on web). |
| **MVP-3** | **Payments (+ taxonomy admin)** ✅ *shipped* | Cash-with-OTP confirmation (resident or provider submits the OTP) + online payment via a `PaymentGateway` abstraction (local stub + Razorpay cloud adapter) + immutable digital receipts with a shareable text. Payments are a loosely-coupled module that never touches the ticket state machine. **Pulled forward from MVP-7:** Super Admin vendor-taxonomy management — verticals ("kinds") are now a lookup table, with CRUD endpoints and a "Taxonomy" screen in the super-admin app; new categories need no migration. |
| **MVP-4** | **Monetization on** ✅ *shipped* | Subscription plans for **communities and vendors** (`com.singlepoint.billing`), lazy FREE default plan so nothing that worked before breaks; `EntitlementService` flipped from a no-op seam to real enforcement — per-calendar-month quotas (`TICKETS_PER_MONTH` / `ADMIN_SEATS` / `OFFERS_PER_MONTH` / `DIRECTORY_LISTING`) return `402 SP-402-QUOTA`, and a lapsed paid plan goes **read-only** (`402 SP-402-SUBSCRIPTION`) after a 7-day grace window — reads always keep working, core ticketing is never metered. Per-period invoices paid through the existing `PaymentGateway` (one-off pay link; Super Admin can also `comp` / `mark-paid`); `BillingRenewalJob` handles period roll → `PAST_DUE` → grace → `EXPIRED`. Manual Super-Admin **Featured vendor tier** (`service_provider.tier`) floats a vendor to the top of the directory + offers feed. Super Admin "Billing" tab + Admin/Provider plan cards (usage bars, pay, self-upgrade). *Deferred: recurring auto-charge, proration, dunning, per-resident plans.* |
| **MVP-5** | **Ticketing depth** ✅ *shipped* | Resident **approval-of-allocation gate** — tenant-configurable, an assigned ticket parks in `PENDING_RESIDENT_APPROVAL` and the provider is engaged only after the resident approves (or declines with a reason). **SLA tracking + breach alerts** — `SlaBreachJob` flags an overdue open ticket once and alerts admins + provider (alert-and-flag only). **Reroute / audit polish** — reroute, provider decline and `ON_HOLD` require a reason; the timeline shows actor names. **Provider ratings aggregation** — `service_provider.rating_avg` / `rating_count`, recomputed on close, sortable in the picker. **Ticket-category admin** — Super Admin owns the global catalogue + any community's list; a community self-manages when `tenant.category_admin = COMMUNITY`. **WhatsApp channel** — additive delivery for ticket notifications, gated by the `WHATSAPP_NOTIFICATIONS` plan entitlement + a per-user opt-in; profile-split sender (log / Meta Cloud API). **Provider directory management + availability** — admin edit / per-community deactivate-restore, provider self-service profile + `AVAILABLE/BUSY/AWAY` (advisory), resident `away_until`. **PII hardening** — ticket free-text + addresses encrypted at rest (`PiiBackfillRunner` for legacy rows), service address masked for non-parties, `@AuditRead` on contact/location reads. *Deferred: name-at-rest encryption, multi-key rotation impl, WhatsApp for promos, allocation-approval timeout, SLA auto-escalation.* |
| **MVP-6** | **Reach expansion** ✅ *shipped* | **Switch-community** — `POST /me/active-community` re-mints a token scoped to another of the resident's communities; `POST /auth/refresh` (fixes the approved-resident stale-token gap); `POST /me/memberships/{t}/leave` (EXITs + flat unlink + fallback). **Direct-to-Provider** — `tenant.direct_service_enabled` (Super Admin + community admin); contact-free `GET /providers`; `POST /tickets` with `providerId` → `request_mode = DIRECT_SERVICE`, straight to `ASSIGNED`; on a provider decline the resident re-picks (`POST /tickets/{id}/rebook`). **Household model** — a `user_tenant_membership` is now user↔flat; `household_role` PRIMARY/SECONDARY; a PRIMARY issues `HOUSEHOLD` invite codes (family joins as SECONDARY, no admin step); one user can hold flats in several communities or several flats in one; **`flatId` is required on raise** once you're in a flat, and every query/feedback/request names its flat. *Deferred to MVP-7: community-less individual service users, multi-community admins, Super-Admin-gated provider onboarding, admin/provider raising a ticket as a flat owner.* |
| **MVP-7** | Actor authority & multi-community ✅ *shipped* | **Provider onboarding moved to the Super Admin** — `SuperAdminProviderController` owns create / verify / tier and `SuperAdminKycController` owns KYC review; a community admin only browses the verified directory (`GET /admin/providers/catalog`) and enrols (`POST /admin/providers/{id}/enrol`), gated by `tenant.provider_onboarding_allowed` (V22). **Community → multiple locations** — `V23` `location` child table (RLS enabled after backfill) + `flat.location_id`; `AdminLocationController`; flats require a location. **Admin ↔ many communities** — `admin_tenant` mapping (V22), `AuthService.resolveActiveTenant` as the single source of truth, `POST /me/active-community` generalised to ADMIN + **SUPER_ADMIN** (acting-as-admin, `JwtAuthFilter` scopes the token to that tenant) + `POST /me/stop-acting`; `ADMIN_SEATS` / admin-notify / billing recipients move to `admin_tenant` via `AdminDirectory`; every admin controller → `hasAnyRole('ADMIN','SUPER_ADMIN')`. **Super-Admin-issued invite codes** — `POST/GET/DELETE /superadmin/tenants/{id}/invite-codes`. **Any flat owner raises** — the RESIDENT-only guard in `TicketService.raise` lifted; an ADMIN / PROVIDER with an ACTIVE flat membership raises for that flat and is the raiser (`loadForActor` / `list` / `close` raiser-aware). **Gated user removal** — `AdminMembershipController` `remove` is a hard `409` while the user has a non-`CLOSED` ticket they raised or an unsettled `ticket_payment`. Full spec: `docs/actor-model.md`. *Deferred: a mobile raise entry point for flat-owning admins / providers.* |
| **MVP-8** | Community-less users & offers depth ✅ *shipped* | **Individual service user with no community** — onboarding ends `READY` with no tenant (`NEEDS_COMMUNITY` retired), tenant-less service requests: `ticket.tenant_id` nullable + a new `app.current_user_id` GUC + a null-tenant RLS branch scoping rows to their raiser + assigned provider (`V24`); direct booking of any verified provider with no tenant (`requireAssignableProviderGlobal`, `GET /providers` global fallback); no admin, no quota, no payment (deferred). **Offer targeting** to a set of communities (`TENANT_LIST` — was already wired) and to **named individuals** by phone (`USER_LIST`, `V25`). **Global redemption cap** hardened with a `PESSIMISTIC_WRITE` lock in `redeem` + `redemptionsRemaining` on the view. **Feedback on an offer** — `offer_feedback` (`V26`, one per user, encrypted comment), `POST/GET /offers/{id}/feedback`, `ratingAvg`/`ratingCount` on the view. Full spec: ADR-034, ADR-035. *Deferred to MVP-9: biometric login + device binding + OTP auto-read; broadcast notifications; paid community-less bookings.* |
| **MVP-9** | Audit visibility & broadcasts ✅ *shipped* | **Super Admin audit-log view** — `GET /superadmin/audit-logs[/actions]`, every filter optional (actor, community, action substring, entity type, success, time window), paged newest-first, names hydrated + phone masked, over the rows `AuditAspect` already writes (`V27` read indexes, native CAST-anchored filter query). **Broadcast announcements** — `com.singlepoint.broadcast`: admin → every active resident of the acting community (`POST /admin/broadcasts`), Super Admin → `ALL_ADMINS` / `ALL_USERS` / a named `COMMUNITY` (`POST /superadmin/broadcasts`); one append-only `broadcast` row (`V28`, body encrypted) + one `notification_outbox` row fanned out by the existing dispatcher (push + in-app); a `kind:"broadcast"` payload discriminator + `notification_preference.broadcast_enabled` (opt-out, default on) gate delivery; a per-sender 60s cooldown + 20/day cap (`SP-429`), no billing meter. `GET/PUT /me/notification-preferences` carries `broadcastEnabled`. Mobile: a Super Admin audit viewer + admin/Super-Admin compose screens + a Settings toggle. Full spec: ADR-036. *Deferred to MVP-10: per-role dashboards; biometric login + device binding + OTP auto-read; reporting / exports (CSV); paid community-less bookings.* |
| **Continuous** | UX & Ops | Icon / loading / imagery polish; safe-area & responsive audit (mobile + web — never hide the top bar or back button); Micrometer metrics + APM; scheduled backups + S3 lifecycle. |
| **MVP-10** | Dashboards, device security & paid bookings ✅ *shipped* | **Per-role dashboards** — `GET /api/v1/dashboard`, one flexible view shaped by the caller's role (ticket status buckets + the action items that need *them* specifically), mounted on the existing resident / admin / provider / Super Admin home screens. **Device-bound sessions** — a JWT can carry a `deviceId` claim; `JwtAuthFilter` rejects a mismatched/missing `X-Device-Id` header (`SP-401-DEVICE`), forcing a fresh OTP sign-in on a copied/replayed token's new device; fully backward compatible (a token with no claim is never gated). **Biometric unlock** (opt-in, default off) gates the whole app behind `expo-local-authentication`; the session token moves from `AsyncStorage` to `expo-secure-store`. **OTP autofill** via built-in `TextInput` props, no native module. **Paid community-less bookings** — `ticket_payment` / `payment_receipt` / `payment_event` relaxed the same way `ticket` was (V24/ADR-034); a community-less direct booking (MVP-8) can now be charged and paid by its assigned provider. Full spec: ADR-037. *Deferred to MVP-11: per-role dashboards' reporting/exports; a Super Admin web console; multi-tenant self-onboarding.* |
| **MVP-11** | Platform scale ✅ *shipped* | **Community self-onboarding** — `POST /onboarding/community` creates a `PENDING_REVIEW` tenant (`V30`); a Super Admin approves it (`/superadmin/community-requests/{id}/approve`) → tenant `ACTIVE`, requester promoted RESIDENT→ADMIN with a "Main" location, or rejects it. **Platform analytics** — `GET /superadmin/analytics?bucket=WEEK\|MONTH` → time-bucketed tickets / offers / users / revenue series + now-totals (communities, residents, providers, open tickets, MRR); Java bucketing, no `date_trunc`. **Super Admin web console** — a new standalone Vite + React app in `admin-web/` (login, dashboard, communities, the onboarding queue, providers + KYC, offers, billing), Super-Admin-only, consuming the existing `/superadmin/*` API; the Expo `(super)` group is untouched. Full spec: ADR-038. *Deferred: reporting / CSV exports; console coverage of taxonomy CRUD, audit viewer, broadcasts, plan CRUD.* |
| **MVP-12** | Reporting & polish ✅ *shipped* | **CSV exports** — `com.singlepoint.export`: a hand-rolled RFC-4180 `CsvWriter` + `ExportService`; `GET /admin/exports/{tickets,payments,members}.csv` (tenant-scoped) and `GET /superadmin/exports/{tickets,offers,communities}.csv` (platform-wide, tickets also `?tenantId=`), filtered by `?from=&to=&status=`. Buffered `byte[]` not `StreamingResponseBody` (RLS ThreadLocals are absent on the async thread). Console `/reports` + Expo-web download rows (web-only; `<a>` can't carry a bearer token → fetch→blob→object-URL). **Console parity** (`admin-web/`) — `/taxonomy` (vendor verticals + vendor categories + global ticket categories CRUD), `/audit` (filterable paged viewer + row detail), `/broadcasts` (compose + history), `/billing` plan create/edit with an entitlement key→number editor, `/communities` lifecycle (suspend / archive / reactivate via `PUT /superadmin/tenants/{id}` `status`, rejects `PENDING_REVIEW`) + a branding drawer; `GET /superadmin/tenants?status=` + `TenantHealth.status` added. **Ops observability** — `micrometer-registry-prometheus` + `/actuator/prometheus` on :18081 tagged `application=single-point`; four `sp.*` domain counters; `docs/ops-runbook.md` (scrape config, Grafana panels, `pg_dump`→S3 backup procedure — documented, not automated). **Mobile UX** — `Themed.Screen` gains safe-area (tab-bar) bottom inset + `loading`/`error`/`empty` slots; screens that returned a bare `<Loading/>` outside `<Screen>` migrated; new `src/components/Icon.tsx` glyph map. Full spec: ADR-039. *Deferred: async "email me the file" exports; Expo-native download (share sheet); full `Icon` rollout.* |

Data-model columns and service seams for later MVPs are pre-placed in MVP-1 where doing so
avoids a migration later (`request_mode`, `sla_due_at`, `flat.owner_user_id`, `tier`,
`EntitlementService`, `vendor_category` taxonomy table, `PushSender` interface).
